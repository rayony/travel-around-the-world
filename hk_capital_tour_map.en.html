How was this route found?

Data assumption (list of states)

This project follows the UN list, snapshot 2026-09-14. Sources still published that day: UN Member States and UN Non-Member States。 Not ISO 3166, and not any one country's recognition list.

  • Set: 193 members (since South Sudan, 14 Jul 2011) + 2 observers (Holy See; State of Palestine since 29 Nov 2012) = 195 rows.
  • Hence no Taiwan / Taipei, and no Kosovo, Western Sahara, Macao, or other non-member / non-observer entities.
  • The 196th point is Hong Kong (CityID 0, nation “-”), start/end only, not treated as a UN state.
  • Short names aligned on 2026-09-14 to the UN page headings: Cabo Verde, Czechia, Türkiye, Congo, Timor-Leste, State of Palestine, Holy See, Côte D'Ivoire. Capitals unchanged (Jerusalem / Ramallah).

The goal is not a shortest path between two points. It is: leave Hong Kong, visit each capital once, return to Hong Kong, minimise the sum of great-circle legs. That is a closed TSP.

1. YardstickSpherical great circle (haversine), not a planar straight line.
2. Build a feasible tourNearest neighbour: always go to the closest unvisited city.
3. Shorten it2-opt: if two edges cross or detour, reverse the segment between them.
4. Honest limitn = 196 cannot be enumerated. These are heuristics, not a proven global optimum.

1. Why TSP, not shortest path?

Dijkstra / A* solve “A to B, nodes may be skipped or reused”. Our constraints are harder:

  • Fixed node set: all 196 places (capitals + Hong Kong).
  • Each city exactly once (Hamiltonian cycle).
  • Start = end = Hong Kong.
  • Edge weight = great-circle distance; complete graph (any pair may be flown).

Exact Held–Karp is O(n² · 2ⁿ). At n = 196, 2¹⁹⁶ is impossible, so we construct then locally search.

2. Distance: great circle / haversine

Treat Earth as a sphere of radius \(R = 6371.0088\) km. The shortest track between latitudes/longitudes φ, λ (radians) is a great-circle arc:

Δφ = φ2 − φ1
Δλ = λ2 − λ1
a = sin²(Δφ/2) + cos φ1 · cos φ2 · sin²(Δλ/2)
d = 2 R arcsin(√a)

A Mercator straight line is not the shortest track, especially across the Pacific or Atlantic. \(\sin(\Delta\lambda/2)\) already handles the date line; Samoa–Kiribati needs no manual ±180° fold.

This run builds a 196×196 matrix once; later comparisons only look it up.

3. Nearest neighbour (greedy construction)

Do not hunt the global optimum yet. Ask only: from here, which unused city is cheapest next? Demo points A–K are reused below.

  1. Stand at the startLeave A (Hong Kong). Unvisited = {B,C,…,K}.
  2. Scan unvisited citiesMeasure distance to every unused city; pick the nearest.
  3. Walk there and strike it offYou are now at the new city. Repeat step 2 until the list is empty.
  4. Final hop homeHowever far, close the tour back to A. This hop is mandatory.
  5. Why many seedsA bad first hop poisons the rest. Run each of the 196 cities as A, keep the shortest cycle, rotate the cut to Hong Kong (length unchanged).

Fast, but early short hops force later ocean crossings and crossings. Step with the buttons.

4. 2-opt (untangle, shorten)

Same tour the neighbour just built. P,Q,R,S are the four ends of two edges, not four cities named ABCD.

  1. Start from a complete tourEvery city is already on the tour; only reconnection is allowed.
  2. Pick two non-adjacent edgesCall them P→Q and R→S. Adjacent edges cannot be swapped without breaking the cycle.
  3. Compare two splicesOld: P–Q + R–S. New: P–R + Q–S. Which pair is shorter?
  4. If the new pair is shorter → reverse Q…RCities stay put; only the middle segment is reversed. Crossings usually vanish.
  5. Sweep all edge pairsAccept improvements and rescan. Stop after a clean pass. Here, about 6–7 passes on 196 cities.
If d(P,R)+d(Q,S) < d(P,Q)+d(R,S), reverse Q…R

The button highlights the first improving pair; ABCD are not pre-chosen.

4b. Farthest insertion

Nearest neighbour walks outward from the current city. Farthest insertion pins the hardest cities into a skeleton first, then fills the gaps. Same points A–K.

  1. Make a tiny tourFrom A, find the farthest city and join the two points both ways. That is the first cycle.
  2. Who is most isolated?For every city still off the tour, measure distance to the nearest city already on it. The largest of those distances is the next city to insert (yellow).
  3. Which edge?For each existing edge X–Y, the extra length is d(X,new)+d(new,Y)−d(X,Y). Insert on the cheapest edge (red dashed).
  4. Pin it inThe tour becomes X→new→Y. Repeat steps 2–3 until every city is on the cycle.
  5. Versus nearest neighbourOn 196 cities the first farthest-insertion tour is about 154,728 km, already better than 171,305 km nearest neighbour; later 2-opt has less room left.

Yellow = next farthest candidate; red dashed = edge that will receive it.

4c. Simulated annealing (2-opt neighbourhood)

2-opt only accepts moves that shorten immediately, so it can stick in a local minimum. Simulated annealing adds a temperature T: longer moves are sometimes taken.

  1. Start from a complete tourThe demo starts from the neighbour tour with a high T.
  2. Pick two random edgesSame as 2-opt: reverse the middle segment and compute Δ (negative = shorter, positive = longer).
  3. Accept or rejectΔ<0: always take it. Δ>0: take it with probability exp(−Δ/T). High T allows uphill moves; T near 0 behaves like plain 2-opt.
  4. Cool downMultiply T by a factor < 1 each step (0.86 in the demo). Later steps look more like ordinary 2-opt.
  5. Result on these 196 citiesStarting from an already 2-opted tour, annealing found no better 2-edge swap. Length stayed 149,529 km. Further cuts need Or-opt / 3-opt.
Accept with probability 1 if Δ<0, else exp(−Δ / T)
Mini demo: random 2-opt; red = an uphill move that may still be accepted
T falls each step. Length may rise before it falls.

4d. Or-opt

2-opt can only reverse a whole segment. Or-opt relocates: pull 1–3 consecutive cities out and insert them elsewhere on the tour.

  1. Choose a chain to moveThe demo moves one city (yellow). The solver also tries chains of 2 and 3.
  2. Cut it outIf B sits in A–B–C, drop A–B and B–C and join A–C. B is briefly off the tour.
  3. Find a new homeScan every remaining edge X–Y. Extra cost of inserting B is d(X,B)+d(B,Y)−d(X,Y).
  4. Move only if the tour shortensPick the cheapest X–Y and become X–B–Y. Each city is still visited once; only B’s neighbours change.
  5. Result hereAfter 2-opt this cut about 1,584 km (149,529 → 147,945), because some cities had been left on the wrong continent.
Mini demo: pull one city out and insert on a cheaper edge
Yellow = city that moves; red = old links; teal = new insertion.

4e. 3-opt

Three edges at once. 2-opt only reverses one segment; 3-opt can also swap the order of two segments.

  1. Cut the tour in three placesYou get three paths. The three cut edges are drawn red.
  2. List legal splicesEach piece may run forward or backward, in any order, as long as the result is still a Hamiltonian cycle.
  3. Score each spliceOnly the three new edges versus the three old ones matter; the rest of the length is unchanged.
  4. Keep it if shorterThe city set is unchanged. Then search the next triple.
  5. On these 196 citiesAfter a legal Or-opt tour, no shorter 3-opt that still visits each city once was found, so the length stays 147,945 km. An earlier shorter figure reused cities and was discarded.

5b. Methods mentioned but not run

Tours on the Map tab used nearest neighbour, farthest insertion, 2-opt, Or-opt, simulated annealing, and one legal 3-opt. The next three methods are shown for principle only; they did not produce the 196-city tours.

Held–Karp dynamic program (exact; not run at 196)

The question is not “who is next” but “which set has been visited, where do we stand, how short is that”. Not used to build the map tours.

  1. Smallest stateOnly {A} visited, standing at A, length 0.
  2. Grow the set by one cityTo have visited {A,B} and stand at B, the only walk is A→B of length d(A,B). Same idea for C.
  3. RecurrenceTo finish set S standing at j: try every previous city i in S, take min(best of S\{j} ending at i + d(i,j)).
  4. Close the tourFor every last city j add d(j,A) and take the min. That is the exact shortest cycle.
  5. Why not 196 citiesAbout n·2ⁿ states. n=4 fits on the canvas; n=20 is ~20 million; n=196 and 2¹⁹⁶ is impossible.
C(S,j)=mini∈S,i≠j[C(S\{j},i)+d(i,j)]; then add d(j,start)

Lin–Kernighan (k is not fixed)

2-opt swaps 2 edges, 3-opt swaps 3. LK lets k grow. LKH was not wired in.

  1. Open the cycleCut one edge (here the edge back to A) to make a path with two tips. Yellow = free tip.
  2. Reattach the tipJoin the free tip to another city (red dashed). One of that city’s old edges is kicked out, so the tip moves.
  3. Watch the running gainSome swaps shorten, some lengthen. Keep adding a cut while the running account still looks promising.
  4. Close when it paysIf rejoining the start shortens the tour, accept that k-opt. Otherwise abandon and cut a different first edge.
  5. Relation to this runLKH on the 196×196 matrix would usually beat Or-opt a little; ocean hops remain. It was left out so every step can be clicked on the canvas.

Solid = current path; red dashed = candidate join; yellow = current tip.

Concorde (LP + cuts; can prove optimality)

Instead of permuting cities, decide which edges are used. Concorde is not installed here; 196 cities usually still finish on a laptop.

  1. Decision variablesEach possible edge e has xe: 1 if the tour uses it, else 0.
  2. First demand “exactly two edges per city”Degree constraints. Problem: two separate triangles also give degree 2 at every vertex, but that is two loops, not one TSP tour.
  3. Forbid subtoursFor any proper subset S, edges inside S cannot close a loop: at most |S|−1 of them. The demo button adds that cut.
  4. Solve over the reals firstAllow fractional x such as 0.3 or 0.7. If fractions or subtours appear, add cuts and resolve.
  5. Then branchForce some edge to 0 or 1 and split the problem. When every x is integer and there is no subtour, that is a proven optimum.
min Σ dexe; degree 2 at each vertex; edges inside any proper S ≤ |S|−1
Mini demo: degree 2 can still be two loops; a cut forbids that subtour
Left: two triangles already have degree 2 at every vertex, but they are not one tour. Right: after the cut they must join.

6. Pseudocode

# Distance
d(i,j) = 2R arcsin sqrt( sin²Δφ/2 + cosφi cosφj sin²Δλ/2 )

# Nearest neighbour
tour ← [s]
U ← all cities except s
while U not empty:
  v ← argmin_{u in U} d(tour.last, u)
  append v; remove v from U
append s

# 2-opt
repeat until no improvement:
  for each pair of edges (A-B), (C-D):
    if d(A,C)+d(B,D) < d(A,B)+d(C,D):
      reverse the segment B..C

  • Farthest insertion：Join Hong Kong to the farthest city, then keep inserting the city farthest from the tour onto the cheapest edge. The first tour already beats nearest neighbour (~155k vs ~171k km), but later 2-opt has less room.
  • Or-opt：Lift a chain of 1–3 cities and insert it elsewhere. Fixes continents that 2-opt cannot see. After 2-opt this cut about 1,580 km.
  • Simulated annealing: Occasionally accept a longer 2-opt to leave a local minimum. Starting from the 2-opt tour, no better 2-edge neighbour was found, so the length stayed put — the 2-opt neighbourhood was already dry.
  • 3-opt：Remove three edges and splice them another way. Can reorder three blocks. On the legal Or-opt tour this run found no shorter Hamiltonian 3-opt, so the best hand-written heuristic here remains Or-opt.

Still not a proven optimum. LKH / Concorde could still cut a little; ocean hops will not vanish. 2-opt already removed the fat 13%; later operators only saved about 1% each.

7. Common misconceptions

  • “Just use a shortest-path algorithm”：Shortest path may skip cities. TSP may not.
  • “Treat lon/lat as planar x,y and use Euclidean distance”：High latitudes stretch and the date line looks like a full-earth hop. Use a great circle.
  • “This is already the mathematical shortest tour”：No. It is a decent approximation. A certificate needs branch-and-cut / Concorde.
